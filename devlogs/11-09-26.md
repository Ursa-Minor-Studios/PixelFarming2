# Placement Validation Completed!

After 7 days, placement validation is now finished, some things need polishing to make it look pretty but the mechanical aspect of that feature is finished. Pixel Farming 2 is a farming game allowing players to place down crops. One important feature that I needed to add was placement validation which prevents players from placing crops on top of each other. This feature I've never done before and wasn't the easiest to figure out. Though 7 days was pretty quick so I'm surprised it only took me a week.

## Progress Updates

### November 2, 2026
Started working on placement validation. During this session my thought process was that I needed to figure out how to first detect that tiles are overlapping with each other. I found this signal* called **body_entered** which by the name suggests I assumed would be able to detect when a node (the tile) enters another node's body.

I also added a collider to the tile called ```ColliderShape2D``` which is a blue box that goes around the object (invisible in the game) which allows you to detect collisions within that rectangle.

I also came across a concept called autoload which allows the script to be referenceable across different scripts (because by default, you can only access a variable in the script it was created in, you generally can't reference a variable from another script unless you make it "global"). To achieve this I went to **top bar > project > project settings > autoloads**

```
func _on_body_entered(body: Node2D) -> void:

  if body.is_in_group("Crops"):

    UserPlacement.currentBuildMode = UserPlacement.BuildingModes[3]

```
In this snippet, I have a function called ```_on_body_entered()``` that is connected through the ```body_entered``` signal. First it checks if the tile is in a group I have defined called "Crops". If the node is in the group then the next line runs. ```UserPlacement.currentBuildMode ...``` looks into the script called ```UserPlacement``` then sets the variable ```currentBuildMode``` to index 3** in the Array called ```BuildingModes``` which index 3 is defined as view mode in my code.

Though this code is insignificant because it didn't do a single thing.

***

**Godot (the game engine) has this feature called signals which allow certain lines of code to run based on specific conditions such as when a button is pressed, held down, timer runs out, etc.*

***Arrays are like variables but can store multiple values (value1, value2, value3,...). You access these values through indexes which start at 0. Value1 = index0, value2 = index 1, value3 = index 2, and so on. I have my building modes in an Array. ```buildingModes = ["Place", "Multi-build", "Delete", "View"```. I have a variable called ```currentBuildMode``` that is set to either one of these values depending on which building mode the user chooses.*

### November 4, 2026
This day I made some progress, figured out how to make the nodes delete when they touch each other. Not what I wanted but saw that as significant progress made because I figured if I can make them delete when touched, I can stop user placement when they touch.

```
func_on_area_entered(area: Area2D) -> void:

  queue_free()
```
In this code, I figured that the ```area_entered``` signal is the one I want to do instead of ```on_body_entered```. I don't know the difference between the both but for my tile, the root node in the tree is a type ```Area2D``` which has something to do with why ```area_entered``` needs to be used.
Then ```queue_free()``` just removes the specified node from the scene. In this case since ```queue_free``` is alone it would remove the node the script is attached to. If I wanted to remove a specific node, I would put ```[node_name].queue_free()```

### November 9, 2026
After a few days asking for help on the [Godot Forum](https://forum.godotengine.org/t/signal-changing-variable-value-not-reflected/146806), I figured out how to prevent users from placing tiles on top of each other. I remembered that static variables exist which allows you to reference variables (like a global variable I mentioned earlier).

In C# (a programming language, Godot uses the GDScript programming language) you just declare a variable as ```static [variable_name];``` which works the exact same way in Java. For GDScript it's a little different but mostly similar.

```
// UserPlacement.gd (This is the user placement script)
public class UserPlacement

var static can_place

...

if can_place == true:
  // Placement logic

...
```
```can_place``` is a conditional boolean (true/false variable) I use to check if someone's able to place. If a tile that will be placed is overlapping with another tile, ```can_place = false``` preventing placement. Otherwise it returns true allowing someone to place.
```public class UserPlacement``` just gives the script a class name allowing it to be referenced. ```can_place``` is the only static variable in my script, so it's the only variable currently that can be referenced from other scripts.

```
// Potato.gd (This script is attached to the first crop in the build list)
_on_area_entered(area: Area2D) -> void:

  UserPlacement.can_place = false

_on_area_exited(area: Area2D) -> void:

  UserPlacement.can_place = true
```

```_on_area_exited``` is another function I added when I connected the ```area_exited``` script. Unlike ```area_entered``` it runs a specific line of code when the overlapping node exits a specific tile's area.
